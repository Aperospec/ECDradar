# 发现与筛选

## 来源组合

选择与本轮题材相符的几类来源，不机械刷全站清单：

| 入口 | 能提供什么 | 不能直接推断什么 |
|---|---|---|
| X 的创作者、研究者、产品团队与话题搜索 | 快速演示、作品与讨论 | 单次 demo 不证明普遍效果；转帖不证明原创 |
| Reddit 的主题社区、项目讨论与评论 | 真实问题、使用反馈、争论和异常线索 | 匿名经验不自动代表普遍事实；赞数不等于可靠性 |
| YouTube、Vimeo、创作者主页与官方视频库 | 视频作品、完整演示、原始媒体 | 公开观看 / 有下载按钮不等于拥有所有再发布权利 |
| Reuters、AP、BBC、The Verge、TechCrunch、Ars Technica、Wired 等报道 | 事件发现、采访、背景与时间线 | 多站转载同一稿不是多个独立来源 |
| 公司公告 / 文档、论文、研究机构、GitHub、官方数据、主办方 | 原始事实、版本、能力入口、事件日程 | 官方宣传不等于我们的实测，媒体资产许可需另查 |
| Hacker News、Product Hunt、Substack、专业社群 | 长尾发现与专业观点 | 排名、订阅和讨论不证明产品可用或授权可复用 |

美国是默认发现重心。英国、德国、法国等按题目补原语言查询，其他国家存在更原始来源时直接使用；避免只收英文二手转述。不把媒体名单当成永久可访问承诺，不绕过付费墙。用户授权材料和公开一手入口可补访问缺口。

## 搜索要找什么

组合主题、实际成果词、事件名、日期和站点，而不只搜宽泛的“AI news”。例如找作品 / demo / interactive / visualization / website / agent workflow，再回溯原始发布。非 AI 热点则寻找能带来具体创作或用途的材料，不强行给所有大新闻加 AI 标签。

热点可从新闻、社交反应和已公布日历进入；计划事件不必先有高点赞。已有 AI 成果优先检查实际展示与可见传播信号；小样本但特别适合账号的内容可保留，并明确尚无高热证据。

把同一事件、版本或作品归为一个候选。记录直接入口、作者 / 权利人、地区 / 原语言，区分发生时间、发表时间、更新时间和观察时间，保留时区并换算北京时间；来源只给日期就注明时间 / 时区未知，不补造精确时刻。

互动数据记录平台、观察时点和具体可见指标；看不到记未知，不填零，不跨平台裸比。新发现的旧视频不能称为最新发布；旧素材在新热点里有新价值时说明新触发点。

## 取舍

综合考虑及时性、可见看点、中文关联、原创空间、事实强度、素材取得、可实现性与账号连续性。画面美、能玩、能解释或能解决问题都可构成价值，不只挑工具安装教程。

核最影响判断的事实；出现矛盾才补独立来源。记者的原创采访 / 调查可是一手报道，不强制让被报道方或政府确认每一条记者事实。

检索项目已有选题、制作中和已发布记录，并做有限中文同题检查；差异可以来自对象、解释、成品或形式。只有确实查过才能声称查重；未覆盖的范围明示，不能说全网没人做过。

分开写观察和判断：

- 观察：来源实际展示什么，哪些事实与热度可查。
- 判断：为什么适合本账号，哪种加工值得投入。
- 未知：需要补的事实、权利、能力与时效；只拦住受影响的动作。
