# 交付与 ECD 交接

## 先给内容，再给依据

直接给最值得考虑的候选及推荐理由，不用网站清单、流程说明或权限说明代替实际发现。候选数量服从质量，少交或暂无合适题目均可。

每项按目标语言（默认简洁中文）说明：

1. **内容是什么**：真实事件 / 作品，一句话概述和直接链接。
2. **为什么值得做**：可见看点、时效、目标读者关联与账号增量；热度依据及未知部分。
3. **我们可以做什么**：至多两个实质不同的创意种子；热点素材 → AI 作用 → 具体成果，或原 AI 视频 + 中文解读。不是最终标题 / 正文。
4. **已经核到什么**：关键事实、版本 / 时间 / 地区、来源角色和仍需补的部分。
5. **有什么材料**：图片 / 数据 / 视频入口，下载和观看状态、本地文件、允许用法、必要署名。
6. **建议下一步**：优先做 / 跟踪 / 不做及原因，剩余窗口与工作量估计；没有测过就不报确定工时。

短雷达结果合并为一个项目文件；选定候选才拆单独 ECD 简报。不要生成空白稿件、固定八件套或需要用户填的表格。复杂来源材料可另附，但核心推荐必须在对话中可理解。

## ECD 接手时带上什么

沿用上面的内容和素材记录，加上用户已确认的运营约束、任务范围、事实 / 创意边界、明确排除的源帖表达。让 ECD 自主判断后续创意发展、传播推进、形式、语言与视觉。

- 未选中的候选进入 ECD 的选题比较；已明确要求制作的题目进入其合法项目入口。按实际 ECD Skill 运行，不把这个简报当成 Treatment 或 Greenlight。
- 不提前锁页数、逐页文案、版式、字体、画风或图像提示词；不先做完全文再让 ECD 名义审批。
- 视频已获可用授权时，把原文件与条件交过去；仅发现来源不变成可直接使用资产。
- 网站、数据或视觉提案无需先做出成品才能交接。公开说“已经做成”时才需要相应真实成果；概念讨论不自动升级为工具性能验证。
- 素材、AI 作用与具体结果应能清楚说明，避免纯悬念；不要求所有标题以“用 AI”开头。新闻直陈事件，第三方演示保留归属。
- 在当前对话调用 ECD 不等于创建新对话或独立 Agent。只有用户明确要求新任务时才创建；若 ECD 不可用，就交付完整简报并说明，不假称已经接收或审核。

## 结束前的人工核对

逐项检查真实交付物：链接实际读过吗？新鲜度和可见指标有依据吗？推荐是否适合账号？事实与创意分开了吗？素材的取得 / 使用状态准确吗？输出是否停在采编范围？

缺项明确记录并只限制受影响的结论或操作。不用占位文本或自动 READY 标签替代判断；不要以这份核对声称获准发布。
